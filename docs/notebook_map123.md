# 无 SSH 的 Map123 云端体验

在已上传并解压的仓库根目录执行。Python 需要 3.10 或以上，建议先运行
`python -m pip install -e .`。本流程不需要 SSH，不启动训练，也不改变防火墙。

## 1. 原始标准场景

```bash
RUN_ID="map123-original-$(date -u +%Y%m%dT%H%M%SZ)-$$"
RUN_DIR="local_data/map123/runs/$RUN_ID"
python -m scripts.run_map123 \
  --scenario original \
  --run-namespace "$RUN_ID" \
  --output-dir "$RUN_DIR" \
  --host 127.0.0.1 --port 8003
```

首次展开缓存约需 1.1 GB 磁盘空间，随后复用。原始数据有 49 个初始单位，
不会将炮兵弹药修改为演示值。`run_map123` 和 `run_maps run map123` 的缺省场景
也已改为 `original`；旧的 `--scenario artillery-ammo2` 演示仍可显式使用。
每次体验创建不同输出目录，不覆盖既有回放。

## 2. 从实例的端口预览打开

使用实例实际提供的认证端口预览或 Jupyter 代理入口。浏览器中的
`127.0.0.1` 指你的电脑，不是云实例；不要直接复制终端打印的本地地址到电脑打开。

如果平台提供的是前缀代理，把实际代理根地址后加上：

- 红方：`/red?token=local-red-seat`
- 蓝方：`/blue?token=local-blue-seat`

例如代理根可能长得像 `https://平台域名/实例路径/proxy/8003`，但这里不是你的实际地址，
必须从你实例的预览入口取得。不要自行猜测实例路径。页面会从自身地址推导挂载前缀，
静态文件、算子图标和 API 请求都留在该前缀内，不需要配置固定域名或修改代码。
支持代理剥离前缀后转发到本地服务器的常见形式；不声明支持所有平台自定义网关。

服务继续只监听 `127.0.0.1`。默认席位 token 是公开的本地开发值，不能当作公网访问安全机制。
不要为了预览改成无认证的公网监听；外层入口必须由平台提供访问认证。
红方 token 不能打开蓝方席位，反之亦然。复盘是 GREEN 全局视角，只应在结束后用于分析。

如果入口打不开，请保留终端启动输出，并提供平台预览 URL 的路径结构及浏览器报错，
不要提供登录凭据或私密 token。

## 3. 结束并保存

至少等一个 tick，在启动终端按一次 Ctrl+C，等待最终 JSON 输出及进程退出。
不要直接关闭实例。记录输出中的回放目录，确认 `replay.zip` 已生成。

## 4. 播放完整地图复盘

在同一个终端中，`RUN_DIR` 仍是刚才的目录；新终端请先把它设为实际回放目录。

```bash
python -m scripts.run_replay_viewer \
  --replay-dir "$RUN_DIR" \
  --native-scenario-map examples/map123/scenario.json \
  --host 127.0.0.1 --port 8000
```

使用平台实际的 8000 端口预览入口打开根页面，建议保留结尾 `/`。
回放只读，不执行新的动作；通过帧/时间控件播放与定位。
原始场景回放必须配原始场景，炮兵演示回放必须配对应变体，不要混用。

## 验证范围

本地自动检查覆盖根路径与模拟 notebook 前缀代理的 HTML、静态文件、API，
以及缺失 token、错误 token、跨席位 token 拒绝。URL 检查覆盖 query token 编码和
目录穿越拒绝。这不是已在你的魔搭实例部署成功的声明，平台具体入口仍需实际验证。

## 后台失败时保留排查资料

若后台推进发生异常，失败会话不能发布为正常复盘；应先查看最初的异常，
而不是只看退出时的 `realtime_session_failed_reset_required`。
新启动器会把已写入的运行资料保留在输出目录同级的
`.本局目录名.incomplete-随机后缀/`，终端打印 `FAILED_RUN_DIAGNOSTICS` 路径。
其中 `failure.json` 记录原始异常类型及摘要，`failure-traceback.txt` 保存有长度上限、
不包含局部变量的异常链。资料只存本机，不上传；可能含游戏运行数据，应按私有资料管理。

该目录不是完整 Replay 包，最后一步可能不完整，不能宣称其已通过严格回放。
请保留它和终端日志，用于定位问题。修复后的新对局使用新输出目录，避免覆盖旧资料。
正常停止并成功发布后，临时运行资料会清理，正式 `replay.zip` 等结果仍保留在原输出目录。
