# 从 v21 到 v22

v22 的软件版本为 0.4.22，裁决语义保持 `native-joint-prestate/1.10`。
此轮目标是清晰交付结构与启动日志，不重写游戏规则、武器数据或模型动作协议。

## 推荐使用独立目录

1. 在旧版按 Ctrl+C 正常停止对局，等待结果发布完成。
2. 保留旧 v21 完整目录。把 v22 完整源码包解压到一个新目录，不在运行中的目录覆盖。
3. 只迁移自己需要的 `local_data` 输入、缓存、场景和运行结果；不要把 `.git`、虚拟环境、旧补丁目录混入新包。
   数据很多时可将既有 `local_data` 作为固定用户目录妥善备份、迁移，切勿先删除旧目录。
4. 在新目录重新 `python -m pip install -e .`，再执行 README 的启动命令。
5. 确认加载路径、端口和红蓝页面，再进行新的对局。不要自动覆盖已有复盘。

完整源码交付不携带用户上传的 Map221/9601 想定、私有原包、历史对局和展开缓存；
这些文件仍由用户保管。公开示例由源码目录的 `examples/maps/catalog.json` 定义。
这次整理不对用户仓库做推送，也不删除旧部署中的任何资料。

## 输出变化

`run_maps start` 默认给出简明准备/加载信息；依赖旧详细准备 JSON 的脚本应显式添加 `--json`。
`--prepare-only --json` 适合只需转换结果的自动化，不会启动服务，其标准输出为准备报告 JSON。
实际启动时 `--json` 还伴有席位 URL 等运行日志，不应把整个标准输出当成单个 JSON 文档。
地图、场景、运行表等内部哈希继续保留，不能从日志变短推断身份验证已被关闭。
默认仍为本机 8003 端口；冲突时选空闲端口，不要误删地图缓存。

## 保持的游戏流程

- 锁定和解锁必须停止、转换完成且非失控；选择武器并确认锁定后，普通直射在静止和机动中均可使用该武器。
- 锁定不免除弹药、冷却、目标和视线条件；解锁不刷新冷却，不补弹。引导和间接火力保留各自部署要求。
- 夺控要求停止、转换完成，并在原夺控格或实际相邻格；机动中的敌方地面算子仍可阻止夺控。
- 到达后的武器展开、锁定就绪状态由后端判断；动作面板位于右上紧凑区域，不影响地图事实。
- 移动目标确认、取消、过期操作保护、受限观察和坦克 H/M/L 已有展示逻辑保持。
- 高差换算与可见/可打击区域使用 v21 的共享逻辑，不为超出表范围的组合凭空填值。
