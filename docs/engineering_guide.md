# 工程导读与维护约定

这份指南面向第一次学习或扩展代码的研究者。项目是 **Native 简化游戏规则引擎**。
研究结果应注明场景、规则语义、观察限制和评测协议。

## 1. 从哪条调用链读起

建议先跑小场景和回归测试，再按下列顺序读代码。无需安装 PyTorch 或启动训练。

| 层 | 主要入口 | 负责什么 | 不应负责什么 |
| --- | --- | --- | --- |
| 状态与裁决 | `core/engine.py`、`core/world.py`、`adjudication/` | 由统一前置状态处理游戏意图，更新权威状态 | 直接调用 LLM、管理模型密钥 |
| 会话与数据边界 | `session/game_session.py`、`session/source_environment.py` | 重置、推进、快照、Source 兼容帧 | 为某个模型偷偷修改游戏规则 |
| 受限观察 | `observations/`、`projection/` | 构造符合席位权限的观察 | 把 GREEN 裁判全局记录作为普通 Agent 输入 |
| 动作授权 | `gateway/decision_window.py`、`operations/` | 决策窗口、合法动作目录、产品化操作校验 | 用过期目录中的索引解释新状态 |
| 训练适配 | `training/env.py` | `reset`、绑定动作、奖励、终止/截断和发布 | 强制所有使用者采用内置学习器 |
| 实时宿主 | `agents/realtime.py` | 时钟、排队、命令生命周期与席位绑定 | 让模型任意推进时间或切换席位 |
| Function Calling | `agents/tool_calling.py` | 有界参数、受限查询、预检、提交及结果查询 | 任意 Python 执行、文件访问或网络代理 |
| 研究评测 | `evaluation/` | 固定任务配置、参考策略、指标与可核验轨迹 | 将示例策略或 smoke suite 宣称为完整科学基准 |
| 界面 | `viewer/` | 显示和交互 | 代替服务端作最终合法性裁决 |

代码中仍保留了兼容、学习器、历史导入和分析等模块。它们有独立用途，不能只因
某个示例没有调用就删掉。新增通用逻辑优先归入已有权威层；适配层不应复制规则。

## 2. 三条不应混用的接入路径

### 同步研究与训练

使用 `NativeTrainingEnv`，选择并记录 `decision-v1` 或 `decision-v2`。
读取 `current_decision_binding`，从这一份绑定的目录选择动作，
通过 `step_bound_action` 提交。观察、动作目录及其版本是一组数据。
`terminated` 与 `truncated` 必须分别保存；达到评测步数上限不等于完成任务。
模型权重更新与梯度计算放在环境外。

### 实时 LLM / JEV 宿主

宿主创建 `RealtimeAgentSession` 并掌握时钟、席位及生命周期，然后向模型开放
绑定席位的 `GameToolAdapter`。预检通过不等于动作已经执行；排队回执也不等于
成功结算。最终使用命令结果确认。

严格的新鲜度检查可能拒绝慢推理结果，这是明确的接口行为，不是让调用方
把旧输入的版本号替换成新版本号。需要宿主选择同步窗口、重新观察/推理，
或使用已有实时 API 的明确调度策略。不要在模型提示词中假装解决竞态。
完整约束见 [Function Calling 文档](game_tool_calling.md)。

重置期间的第二次重置会明确拒绝；关闭会话后，尚未返回的初始化工厂不能再
安装新 episode。初始化失败后旧席位绑定失效，需要成功重置后重新获取。
实时运行和关闭等待的数值预算必须为有限正数且不超过 Python 线程等待上限；
只有允许 `None` 的关闭接口才将其解释为无限等待。不要用 NaN 或无穷值表示不限时。

### 离线数据与审计

保存原始轨迹及版本信息，再由回放工具复核。审计者可以查看裁判信息，但
策略输入不得因此获得隐藏状态。不同观察协议、奖励策略、规则语义或任务限制的
实验不能仅按一个总分直接比较。

## 3. 什么叫“优化没有改坏”

性能改动必须同时提供：

1. 同一规则语义、场景、种子和动作序列下的前后结果。
2. 权威状态/轨迹及双方受限观察的等价核验，必要时包括严格回放。
3. 同机、非并行竞争的测量；注明预热、样本量、分位数与运行条件。
4. 保留原始 JSON，不仅记录加速倍数。小样本和共享主机结果应明确标注。
5. 覆盖缓存失效、可变对象隔离、重置、异常路径和席位隔离的回归测试。

优先消除重复构造、复制和序列化；仅在剖析显示计算内核确实占主要耗时、
且跨语言边界成本值得时引入 C++。不能用降低验证强度、泄漏状态、跳过回放记录、
改变随机数消费顺序或静默削减功能来换取“提速”。

`native-joint-prestate/1.3` 包含用户指定的普通直射超距空射规则。
它相对 `/1.2` 是有意的语义变化，不是性能等价改写。旧版测试结果和旧版轨迹
保留其原始身份，参见 [规则说明](direct_fire_range_policy.md)。

## 4. 本地质量检查

在源码根目录：

```bash
python -m pip install -e '.[dev]'
python -m devtools.health release
python devtools/run_checks.py
PYTHONPATH=src python checks/verify_training_contracts.py . /tmp/training-check-new
PYTHONPATH=src python checks/verify_public_scenarios.py . /tmp/scenario-check-new
```

输出目录使用新的空路径，不要覆盖已归档的实验。Windows 可先设置 `PYTHONPATH=src`
或使用上面的可编辑安装，再省略命令前的环境变量写法。

Node.js 用于前端交互逻辑测试；本地未安装时该测试会显示 skipped，而不是 passed。
CI 配置会安装 Node.js，并在 Python 3.10、3.12、3.13 上执行这些检查及 benchmark smoke。
CI 状态以实际运行结果为准，运行范围为上述检查及 benchmark smoke。

## 5. 修改与评审标准

- 每个改动解决一个明确问题；先写失败用例或保存可复现基线。
- 公共接口优先向后兼容的增量扩展。必要的语义变化应升级相应身份，写迁移说明。
- 不把绝对路径、认证信息、展开的地图缓存、模型权重或本地运行记录提交源码。
- 异常要保留可定位信息。不要吞掉错误后返回成功，也不要将进程退出伪装为策略失败。
- 仅对真正共享的行为抽象，不为减少行数创建难以追踪的通用框架。
- 原有大模块可以逐步分解，但必须以契约和回归证据保护边界，不能一次性重排整个项目。

## 6. 发布与研究证据的边界

当前发布仍以 **完整源码目录** 为单位。运行所需的 `examples/`、`config/` 和
`docs/rules/` 需要一起保留；不能把能构建 wheel 当作所有场景和数据已经打包的证明。
基础引擎无第三方运行依赖，PyTorch 是可选学习器依赖。

研究评测工具用于形成可复现的实验记录，不自动证明统计显著性、泛化、现实任务
有效性或安全性。正式论文仍需要预先定义任务集与划分、足够的随机种子、
模型/推理预算、对照方法、失败案例，以及与结论相匹配的统计分析。
