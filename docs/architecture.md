# v22 架构与数据契约

## 单一裁决链

```text
地图 ZIP + Source 想定 / Native 场景
  → data / io：转换、补充明确 Native 约定、绑定移动和视线表
  → ScenarioBundle → ScenarioMatchFactory
  → GameSession → NativeEngine.step（唯一权威裁决）
  → 受限观察 + 操作状态 → 模型适配器 / 浏览器
  → 回放、分析、命令记录
```

浏览器和模型共享服务端操作校验，不各自实现战斗裁决。
`preview_game_operation` 只是预检；提交回执不是动作完成，须查询最终执行结果。
持续动作由后续 Tick 推进。失效的观察绑定或动作目录不能替换版本号后重用。

## 五类职责及支持模块

1. **游戏逻辑**：`core` 管权威世界；`adjudication`、`movement`、`visibility`、`rules`、`systems`
   管既有规则。v22 沿用 v21 的裁决语义 1.10，前端隐藏按钮不代表服务端规则改变。
2. **操作功能**：`operations`、`gateway`、`session` 负责席位隔离、预检和提交；
   `agents/realtime.py` 负责时钟和队列。停止、锁定、展开等状态转换完成前不能绕过就绪条件。
3. **模型接口**：`agents/tool_calling.py` 提供工具，`training` 提供同步环境；
   `observations`、`llm_input` 提供受限数据。模型推理、凭据和网络调度属于外部宿主。
4. **数据接口**：`data`、`io`、`compat`、`shareddata` 与 `config` 保持当前转换和模式；
   `docs/rules` 为运行校验所需来源，不是可随意删除的旧文档。
5. **渲染**：`viewer`、`rendering`、`projection` 显示服务端事实。
   区域覆盖来自后端视线/武器范围查询，不等于当前弹药、冷却和目标条件均满足。

`replay`、`analysis`、`alignment`、`calibration`、`evaluation`、`backends` 是现有接口、复盘、
评测或规则校核的支持模块。它们不额外拥有一套线上游戏状态；仅因日常启动未调用而删除会破坏公开入口。
保留既有模块路径与 CLI，开发检查留在 `checks` / `devtools`，测量资料留在 `benchmarks`。

可选的 `config/capabilities` 演示认证目录不等于引擎动作能力。旧条目引用了未随源码提供的
演示和认证资料，因此 v22 不再将它们宣传为已认证演示；现有游戏动作、模型工具和规则实现不受此目录影响。
未分发的可选演示需要自行提供目录文件，不能用缺失文件冒充通过验收。

## 加载边界

- 原始地图包含 `basic.json`、移动代价和静态视线数据。兼容参数只能明确指定，不能凭地图名猜测。
- Source 想定转换结果包括 Native 场景、明确补充约定、来源副本和转换报告；缺失字段不伪装为原始事实。
- 场景路障参与地图运行身份绑定，不允许跨不同想定误用缓存。
- 高程以地图声明的 `elevation_kind` / `elevation_unit_m` 精确换算；不统一强除以 10。
- `ScenarioBundle` 持有规范数据，返回隔离的引擎与渲染投影；不能为了少一次复制暴露可变共享状态。
- 训练策略只可读自己的 RED / BLUE 观察；GREEN 全局证据只用于裁判、回放和审计。

## 为什么仍有哈希和运行编号

| 内容 | 保留原因 |
| --- | --- |
| 地图源、运行表和清单哈希 | 检测损坏和错误缓存绑定 |
| 场景、世界状态、观察/规划身份 | 确定性、纯度校验、阻止过期动作 |
| 回放、规则语义和训练 checkpoint 身份 | 拒绝错误版本的重执行或恢复 |
| 每场唯一运行目录编号 | 避免覆盖旧结果，不是需要人工填写的参数 |

这些身份留在机器记录中。默认终端只需告诉操作者加载了什么、保存到哪里、如何访问；
需要诊断时使用详细 JSON。删掉打印不等于删掉校验，更不能将可变世界的哈希永久缓存。

## 错误与验证

端口占用属于服务启动失败；地图准备成功并不表示端口已绑定。
准备失败不能显示“新对局已启动”；保留失败运行资料用于定位第一条异常。
严格回放需匹配裁决语义；旧历史记录可作为记录查看，不因此允许用新规则冒充原规则重执行。

验证入口、隔离要求和性能证据标准见 [工程导读](engineering_guide.md)。
